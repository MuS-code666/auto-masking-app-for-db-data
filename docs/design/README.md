# 業務データのローカルマスキングアプリ 設計書

版: 0.1（初版・設計フェーズ） / 作成日: 2026-11-03

## 位置付け

Excel（.xlsx）・CSV の複数の表に含まれる、機密性のある名称や識別コードを、ローカル環境だけで連番名称・代替コードに置き換えるWindowsアプリの設計書です。

**本アプリは名称・識別情報の置換を行うものであり、再識別できないことを保証する匿名化製品ではありません。** 金額・数量・日付・取引パターンは原則としてそのまま残ります。

## 前提となる既存環境の確認結果（2026-11-03 時点）

- リポジトリには `CLAUDE.md` のみが存在し、`AGENTS.md`、既存実装、既存の設計文書はない。
- 既存のローカルLLMマスクアプリのソースは提供されていないため、その内部仕様は参照・推測せず独立して設計した。
- 開発・試験には合成データのみを用いる（実データはClaude Codeに読み込ませない）。

## 設計の要点（要約）

1. **決定的な変換が中核、LLMは補助**：変換は「確定した設定」と「確定した対応表」だけで行う。LLMは列の種類推定と自由記述の候補検出に限定し、出力は必ず人の確認を経る。LLMがなくても全機能（候補提案を除く）が動く。
2. **プロジェクト単位の対応表**：対象（顧客・製品など）ごとに内部IDを持ち、元コード・元名称・別名・変換後コード・変換後名称を関連付ける。自動統合はしない。
3. **番号は確保したら二度と使い回さない**：プレビュー時点で番号を確保し、取消時は欠番にする。これにより「プレビューと出力で番号が変わる」ことを防ぐ。
4. **Excelはパッケージ部品単位で必要箇所だけ書き換える**：ライブラリで読み込んで保存し直す方式を採らず、.xlsx（ZIP内のXML）のセル値部分だけを書き換え、他の部品は原則バイト単位で維持する。把握していない部品があれば出力を止める（許可リスト方式）。
5. **出力前に全体を再読込して検証**：維持対象セルの完全一致、関係の結合件数、元語句の残存（パッケージ内の全テキスト部品・ファイル名・シート名を含む）を検査し、問題があれば正常完了としない。
6. **対応表の確定 → 外部出力 の順で処理**：途中で失敗しても「外部に出た成果物の対応が未確定」という状態を作らない。

## 用語（画面表示用と内部用）

| 画面で使う言葉 | 内部・設計上の名称 | 意味 |
|---|---|---|
| プロジェクト | project | 案件単位の作業場所。対応表はプロジェクト間で共有しない |
| 種類 | entity type | 顧客・製品・原料・人物 など |
| 対象 | entity | 個々の顧客・製品など（内部IDを持つ） |
| 対応表 | master | 対象と元コード・元名称・変換後名称等の対応 |
| コード体系 | code scheme | 「販売管理の得意先CD」など、コードの出どころと形式 |
| 共通項目 | column group | 「得意先CD」「顧客番号」など、ファイルごとに名前が違う同じ意味の列のまとまり |
| 表の範囲 | table region | シート上の見出し行・データ開始・終了位置 |
| 変換作業 | run | 取込から出力までの1回分の作業（履歴単位） |
| 要確認 | review item | 人の判断が必要な項目 |
