# 01 要求定義

各項目を次の3区分で記載する。

- **【確定】** 依頼書で決定済みの事項
- **【提案】** 本設計で置いた推奨案（変更可能）
- **【未決】** 判断が必要な事項（推奨初期値は [10_open_issues.md](10_open_issues.md)）

## 1. 目的

【確定】集計・分析アプリの試作（営業提案・社内承認段階）に少量の実データを用いるため、機密性のある名称・識別情報をローカルで変換し、生成AIを用いたコーディングに渡せる状態にする。

【確定】名称等の置換であり、再識別不可能な匿名化を保証しない。金額・数量・取引パターンは残る。この前提を画面文言・出力時表示・ドキュメントに明記する。

【提案】画面上の固定表示文言（例）：
> この処理は名称・コード等を置き換えるものです。金額・数量・日付・取引の傾向は残るため、内容から取引先等が推測される可能性があります。「匿名化」を保証するものではありません。

## 2. 機能要求

### 2.1 プロジェクト

| 区分 | 要求 |
|---|---|
| 確定 | プロジェクトごとに共通の対応表を継続利用し、プロジェクト間で分離する |
| 確定 | 途中保存と再開ができる。作業中プロジェクト名を常時表示する |
| 提案 | 1プロジェクト＝1フォルダ＋1データベースファイル。同時に開けるプロジェクトは1つ（誤混用防止） |
| 提案 | プロジェクトごとに識別色を設定でき、画面上部の帯に名称と色を常時表示する |

### 2.2 取込

| 区分 | 要求 |
|---|---|
| 確定 | .xlsx と .csv。複数ファイル・複数シート・異なる列名や構造を扱う |
| 確定 | 見出し行、データ開始・終了位置を指定できる。表外のタイトル・注記・非表示領域の扱いを明示する |
| 確定 | 設定の再利用はファイル名だけで判断しない |
| 確定 | 未対応機能・暗号化・破損ファイルを検出して案内する |
| 提案 | 取込時に原本を読み取り専用でプロジェクト内に複製し、ハッシュ値で同一性を管理する（[10_open_issues.md](10_open_issues.md) 未決2） |
| 提案 | 1シートに複数の表がある場合、表の範囲を複数登録できる（初期版は自動推定1つ＋手動追加） |

### 2.3 列ごとの処理

【確定】処理方法は「維持／置換／内容削除／自由記述内の検出・置換」の4種。情報種類（顧客名・製品コード等）と処理方法は別項目として持つ。

【確定】初期設定例：

| 情報種類 | 初期の処理 |
|---|---|
| 顧客名・会社名・個人名・製品名・原料名 | 連番名称へ置換 |
| 顧客コード・製品コード | 制約を満たす代替コードへ置換 |
| 住所・電話番号・メール | 置換または内容削除を列ごとに指定 |
| 金額・単価・数量・原価・日付 | 維持 |
| 摘要・備考 | 自由記述内を検査 |

【提案】住所・電話・メールの初期値は「内容削除」。置換を選んだ場合は形式を保ったダミー値（例：`000-0000-0001`、`user0001@example.invalid`）にする。

【提案】住所の粒度保持（都道府県まで残す等）は拡張機能とし、初期版は「全体を置換」または「内容削除」のみ。ただし拡張しやすいよう、処理方法に「部分維持」を追加できるデータ構造にしておく。

### 2.4 対応表

【確定】
- 対象ごとに内部IDを持ち、元コード・元名称・別名・変換後コード・変換後名称を関連付ける。
- 名称は種類ごとの連番（顧客0001 等）。番号は振り直さず、欠番を許容し、再利用しない。
- 同じ対象は全ファイルで同じ変換先。新しいファイルでは既存対応を再利用し、新しい対象だけ追加する。
- コードがある場合は、明示したコード体系・範囲内でコードを優先して照合する。
- 列名が同じ・値が似ているだけで自動統合しない。同姓同名・類似名称を勝手に同一視しない。
- 表記の正規化は照合候補を出すためだけに使い、元の値は失わない。
- 既存対応は原則変えない。統合・分離・変更は、影響するファイルと過去の出力が分かる操作にする。
- 出力ごとに使用した設定・対応表の版を追跡できる。外部に渡す成果物には元語句・対応表を含めない。

### 2.5 確認・検証・出力

【確定】
- 初回はアプリが設定候補を推定し人が確認・修正する。以後は変更箇所・新規対象・曖昧な判断だけを確認する。
- プレビューと確定出力で同じ対応を使う。
- 元と同じファイル形式で出力し、元ファイルを上書きしない。
- 未解決の機密情報候補や変換由来の不整合があれば正常完了としない。「完全匿名化済み」と表示しない。
- ファイル名・シート名に含まれる機密情報も確認する。

### 2.6 LLM

【確定】LLMは列名と最小限のサンプルからの種類推定と、自由記述の未登録候補検出に限定する。全行をLLMで書き換えない。LLM出力は候補として人が確認する。セル内容は信頼しないデータとして扱う。

【提案】LLMが未導入・停止・応答失敗でも、規則による推定（列名辞書・正規表現）と手動設定で全工程を完了できる。

## 3. 非機能要求

| 区分 | 項目 | 要求 |
|---|---|---|
| 確定 | 実行環境 | Windows PC（メモリ32GB、Core Ultra 7 258V、Arc 140V）。GPU利用可否は実機検証事項。CPUで動く経路を持つ |
| 確定 | ネットワーク | 業務データ処理はオフラインで完結。元ファイル・値・対応表を外部へ送らない。外部テレメトリ・自動クラッシュ送信を前提にしない |
| 確定 | 分離 | 初回取得（アプリ・モデル・依存）と日常の業務データ処理を分ける。自動更新を業務処理と切り離す |
| 確定 | アカウント | Google等のアカウント接続を必須にしない |
| 確定 | 保存分離 | 元ファイル、対応表、作業データ、外部提供用ファイルを分離。外部向けフォルダに対応表・原本・機密を含む診断レポートを混在させない |
| 確定 | 記録 | ログ・エラー・キャッシュ・一時ファイル・モデル入出力記録に元値を不用意に残さない |
| 未決 | 暗号化 | 保存データの暗号化方式は未決定（選択肢は [07_verification_output.md](07_verification_output.md) 6章） |
| 未決 | 性能目標 | 対象ファイル規模が与えられていないため目標値は未設定。計測計画のみ定める（[08_performance_plan.md](08_performance_plan.md)） |
| 提案 | 利用者 | 単一利用者・単一端末。同時編集は対象外 |
| 提案 | 導入 | 管理者権限なしのユーザー単位インストールを基本とする |

## 4. 対象外（初期版）と理由・拡張の境界

| 対象外 | 理由 | 拡張できる境界 |
|---|---|---|
| 元語句への復元 | 必須でなく、復元機能は流出時のリスクを高める | 対応表は保持しているため、内部専用の逆変換機能を後から追加可能 |
| クラウドスプレッドシート直結 | アカウント接続・ネットワークを要する | 取込部（Reader）を差し替え可能な構成にする |
| 外部生成AIへの自動送信 | 外部送信をしない方針 | 対象外のまま。出力フォルダを利用者が手動で渡す |
| 金額・数量等の擬似データ化 | 試作の説得力を損ない、検証も複雑化 | 列処理に「数値変換」を追加できるデータ構造 |
| 分析アプリの自動生成 | 本アプリの目的外 | ― |
| PDF・画像OCR | 精度・検証の保証が困難 | 画像はファイル内に存在することを検出して警告する |
| Excel機能の完全維持 | ライブラリ・方式上不可能 | 機能ごとの対応表で範囲を明示（[06_file_support.md](06_file_support.md)） |
| 複数利用者の同時編集 | 整合性設計が大きく変わる | プロジェクトのロックファイルで単一利用を保証 |
| .xls、.xlsm、.xlsb、.ods | 形式・マクロの安全性検証が別途必要 | 取込時に検出し案内。Excelで.xlsxに保存し直す手順を表示 |
