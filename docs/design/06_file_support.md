## 2. Excel 出力方式：パッケージ部品単位の書き換え

.xlsx は ZIP の中に XML 等の部品が入った形式である。本アプリは**ライブラリで読み込んで保存し直す方式を採らない**。理由は、一般的なライブラリは読み込めない要素を保存時に落とすことがあるためである（openpyxl の公式文書にも、既存ファイルの一部要素は読み込まれず、開いて保存すると図形が失われる旨の注意がある）。

方式：
1. ZIP 内の全部品を列挙し、部品の種類を既知の一覧（許可リスト）と照合する。**一覧にない部品があれば停止**する。
2. 書き換えるのは次だけとする。
   - ワークシート部品のセル値（`<c>` 要素の値・型属性）
   - 共有文字列表（sharedStrings.xml）：**全体を作り直す**。元の表にあったが、どのセルからも参照されていない文字列（過去の編集の残骸）も含めて元の語句を残さないため
   - 本表で「置換」とした部品（数式キャッシュ、グラフのキャッシュ等）
   - 「除去」を選んだ部品（関係定義・コンテンツ種別定義も整合させて除去）
   - 文書プロパティ（初期化）
3. それ以外の部品は**元のバイト列のまま**格納する。
4. ZIP のタイムスタンプは固定値にし、同じ入力から同じ出力を作る。

## 3. Excel 機能の対応一覧

区分：**対応**（維持し、必要な置換を行う）／**制約付き**（条件付きで維持。条件外は警告または停止）／**除去可能**（利用者が選べば除去して出力）／**未対応**（検出したら停止）

| 機能 | 区分 | 元語句が残り得る場所 | 取込時の検出 | 初期版の扱い |
|---|---|---|---|---|
| セル値（文字列・数値・日付・真偽・エラー） | 対応 | ― | ― | 列規則どおり変換。日付は数値＋表示形式のまま維持 |
| リッチテキスト（セル内の部分書式） | 制約付き | 各書式区間の文字列 | 区間の有無 | 置換が必要なセルは書式区間を結合し先頭区間の書式で1つにする（警告表示）。置換不要なら維持 |
| 書式・表示形式・列幅・条件付き書式の書式 | 対応 | ― | ― | 部品を維持 |
| 条件付き書式・入力規則の条件式・一覧 | 制約付き | 「="さくら商事"」などの文字列定数、一覧の値 | 式・一覧を全文検査 | 元語句を含む場合は停止（後続で置換対応） |
| 数式 | 制約付き（初期版で重点対応） | 数式中の文字列定数、シート名・外部参照、**計算結果のキャッシュ値** | 全数式を字句解析して検査 | 数式文字列は維持。文字列定数が登録語句と**完全一致**する場合は対応表で置換（4.1）。部分一致・外部ブック参照・元語句を含むシート名参照は停止（「値に変換して出力」を選択可）。キャッシュ値は4章 |
| 共有数式・配列数式 | 制約付き | 同上 | 同上 | 同上 |
| 結合セル | 対応 | ― | 検出 | 維持。見出し・範囲推定で考慮 |
| テーブル（リスト） | 制約付き | テーブル名、列名キャッシュ、集計行の式 | テーブル部品を検査 | 見出しを置換しない限り維持。テーブル名等に元語句があれば停止 |
| グラフ | 制約付き | 系列名・項目名のキャッシュ（文字列キャッシュ）、タイトル | 全文検査 | キャッシュ値を対応表で置換（完全一致のみ）。対応できない文字列が残れば停止、または「グラフを除去」 |
| ピボットテーブル | 未対応（除去可能は後続） | ピボットキャッシュに元データの写しが丸ごと入る | ピボット部品の有無 | 停止。「Excelでピボットを削除または値に貼り付けてから再取込」を案内 |
| 外部リンク | 未対応 | 外部ブックのパス・キャッシュ値 | externalLink 部品 | 停止。「Excelでリンクの解除」を案内 |
| Power Query・データ接続・データモデル | 未対応 | 接続文字列、データの写し | connections / customXml / model 部品 | 停止 |
| コメント（メモ）・スレッド形式コメント | 除去可能 | 本文、作成者名、人物一覧 | 部品の有無と件数 | 既定は停止し「コメントを除去して出力」を選択可。置換対応は後続 |
| 文書プロパティ（作成者・最終更新者・会社・タイトル等） | 対応（初期化） | 作成者名・会社名 | core/app/custom 部品 | 既定で空に初期化（画面に表示） |

| 非表示行・列 | 対応 | セル値 | 検出 | 表の範囲内なら通常どおり変換。範囲外は検査対象 |
| 表の範囲外のセル（タイトル・注記・欄外） | 対応 | セル値 | 範囲推定時に検出 | 領域ごとに「そのまま／文章内を検査／内容を消す」を選択。既定は「文章内を検査」 |

| ヘッダー・フッター | 制約付き | 印刷用の文字列 | シート部品を検査 | 元語句を含む場合は文章内置換（確認後） |
| 図形・テキストボックス | 制約付き | 図形内の文字列 | 描画部品を検査 | 元語句がなければ維持。あれば停止（置換は後続） |
| 画像 | 制約付き | 画像内の文字（OCRしない） | 画像部品の有無 | 「画像の中身は検査しません」と表示し、確認チェックで続行。または除去 |
| プリンタ設定（バイナリ） | 対応 | 通常は名称を含まない | 有無 | 維持（検査対象外と明示） |
| 計算チェーン | 対応 | ― | ― | 維持（または除去してExcelに再作成させる。実装時に検証） |
| マクロ・ActiveX | 未対応 | ― | 部品の有無 | 停止（.xlsx に通常含まれないが検出する） |
| 埋め込みオブジェクト（OLE） | 未対応 | 中身全体 | 部品の有無 | 停止 |
| 変更履歴（共有ブック） | 未対応 | 過去の値 | revisions 部品 | 停止 |
| 許可リストにない部品 | 未対応 | 不明 | 部品一覧 | 停止（部品名を表示） |

## 4. 数式のキャッシュ値の扱い

数式セルには計算結果が「キャッシュ値」として保存されている。例えば `=VLOOKUP(A2,顧客!A:B,2,FALSE)` のキャッシュ値には元の顧客名が入っている。数式文字列だけ維持しても、キャッシュ値に元語句が残る。また pandas 等の多くの読込ツールは数式ではなくキャッシュ値を読むため、キャッシュ値の扱いは試作に直接影響する。

| 選択肢 | 内容 | 評価 |
|---|---|---|
| ①対応表で置換＋開いた時に再計算（推奨・既定） | 文字列のキャッシュ値を自由記述と同じ規則で置換し、ブックに「開いたときに再計算」を設定 | 参照系の数式では再計算結果と一致する。LEFT 等で文字を切り出す数式では一致しない場合があるため、元語句を参照する数式の件数を警告表示 |
| ②キャッシュ値を消去＋再計算設定 | 値を空にする | Excelでは再計算されるが、読込ツールでは空になる |
| ③値に変換 | 数式を削除し置換後の値だけ残す | 確実だが数式が失われる |

数値のキャッシュ値（金額の合計等）は維持する。ただし数式が置換対象の列（コード等）を数値として参照している場合は、結果が変わり得るため警告する。

### 4.1 数式を多用するファイルへの対応（2026-11-03 回答を受けて追加）

利用者のファイルでは数式がよく使われ、それ以外の機能はまれである。このため、初期版では数式の扱いを重点的に作り込み、ピボット・グラフ・外部リンク・コメント等は「検出して停止または除去」にとどめる。

| 数式の型（例） | 数式文字列 | キャッシュ値 | 初期版 |
|---|---|---|---|
| 参照・四則演算（`=C2*D2`、`=SUM(E2:E100)`） | 維持 | 数値は維持 | 対応 |
| 参照系（`=VLOOKUP(A2,顧客!A:B,2,FALSE)`、`XLOOKUP`、`INDEX/MATCH`） | 維持 | 文字列は対応表で置換（参照先も同じ対応で置換されるため、再計算結果と一致） | 対応 |
| 条件集計（`=SUMIF(B:B,"さくら商事",E:E)`） | 文字列定数が登録語句と完全一致 → 置換（`"顧客0003"`）。参照先も同じ対応で置換されるため集計結果は変わらない | 数値は維持 | 対応 |
| 条件分岐（`=IF(B2="さくら商事","重点","")`） | 同上 | 同上 | 対応 |
| 文字列操作（`=LEFT(B2,3)`、`=B2&"様"`、`TEXTJOIN`） | 維持 | 置換後の値を基準にした結果と一致しない可能性あり（例：LEFT は元の名称の一部を返していた） | 警告。件数と場所を表示し「開いたときに再計算」設定で出力。利用者は「値に変換」も選択可 |
| 文字列定数に語句の一部を含む（`=COUNTIF(B:B,"*さくら*")`） | ワイルドカード・部分一致は意味が変わるため自動置換しない | ― | 停止。「値に変換」または利用者による数式修正を案内 |
| 他シート参照（`=顧客!B2`） | シート名に元語句がなければ維持 | 文字列は対応表で置換 | 対応 |
| 外部ブック参照（`=[売上.xlsx]Sheet1!A1`） | ― | ― | 停止（外部リンク） |
| 名前定義を使う数式 | 維持（名前定義側を検査） | 同上 | 対応 |

実装上の要点：
- 数式は字句解析器で「文字列定数」「シート参照」「関数名」「セル参照」に分解し、文字列定数だけを置換対象にする（数式全体への単純な文字列置換は行わない）。
- 置換後の数式とキャッシュ値の整合は、合成データの試験で、表計算ソフトの再計算結果と比較して確認する（開発時のみ。LibreOffice の自動実行を試験用の比較に使うことを検討。製品には同梱しない）。最終確認は Excel で手作業で行う。
- 「開いたときに再計算」を設定したファイルは、Excel で開いて閉じる際に保存確認が出る場合がある。その旨を出力メモに記載する。

## 5. CSV

### 5.1 検出と確認

| 項目 | 検出方法 | 確認 |
|---|---|---|
| 文字コード | BOM（UTF-8 / UTF-16）→ UTF-8 として厳密に復号できるか → CP932（Shift_JIS）として厳密に復号できるか。charset-normalizer は参考表示のみ | 推定結果と先頭数行の表示で人が確認。どれでも復号できなければ停止 |
| BOM | 先頭バイト | 有無を記録し出力で再現 |
| 区切り文字 | 候補（, タブ ; \|）ごとに各行のフィールド数の一貫性で推定 | 人が確認 |
| 改行 | CRLF / LF / CR の出現数。混在は警告 | 出力は元の改行を行ごとに再現 |
| 引用符 | フィールドごとに引用符の有無を記録 | ― |
| 末尾改行 | ファイル末尾の改行の有無 | 再現 |

### 5.2 型を変換しない

全フィールドを**文字列のまま**扱う。先頭ゼロ（`00123`）、長い数字（`12345678901234567890`）、空欄と空文字（`,,` と `,"",`）、日付に似た文字列（`2024/1/2`、`1-2`）を一切変換しない。型の推定は列の種類推定の参考にのみ使い、値は変えない。

### 5.3 同じ形式で出力する範囲

| 維持する | 再直列化で変わり得る |
|---|---|
| 文字コード、BOM有無、区切り文字、行ごとの改行、末尾改行の有無、行数・列数・行順、変更のないフィールドの文字列と引用符の有無、変更のない行のバイト列 | 置換したフィールドの引用符（元が引用符なしでも、置換後の値に区切り文字・引用符・改行が含まれる場合は引用符を付ける）。置換後の値が元の文字コードで表現できない場合は停止（連番名称は CP932 で表現可能） |

**変更のない行は元のバイト列をそのまま出力**し、変更のある行も変更したフィールドだけを組み立て直す。したがってバイト一致はしないが、差分は置換箇所に限定される。

## 6. 検査の限界（明示する事項）

- 画像・埋め込みバイナリの中身は検査しない。
- 元語句の検査は「対応表・追加語句に登録された語句」と「規則・AIで検出した候補」に対して行う。**登録も検出もされていない機密情報は見つけられない**。
- 正規化（全角半角等）の違いを考慮した残存検査を行うが、言い換え・略称・ローマ字表記等、登録されていない表記は検出できない。
- 金額・数量・日付・取引パターンから取引先等が推測される可能性は残る（本アプリの対象外）。
