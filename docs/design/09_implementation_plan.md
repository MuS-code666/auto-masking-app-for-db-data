受入条件の確認（`tests/scenarios/test_acceptance_freetext.py`、`tests/test_freetext.py`、合成データ）：
- 備考欄を含む基準ケース（マスタ xlsx・売上/仕入 CSV・製造原価 xlsx）で残存0件。顧客名（同名・略称を含む）・電話番号・担当者の姓が出力のどこにも残らない。「〇〇様より追加注文」は同じ行の得意先名と同じ変換後名称になる。置換する語のない文章はそのまま。合格
- 短い語（原料名「砂糖」）・置換先が複数の語（顧客と製品で同じ「さくら」、同名の別顧客）・未登録の法人名・メールが要確認に出て、判断するまで出力できない。判断どおりに置換され、翌月は前回の判断・登録で要確認なしに置換される。短い語を「問題なし」にすればそのまま出力できる。合格
- 表外（見出しより上のタイトル）の顧客名の置換。合格
- S9 のヘッダー・フッター、S10 のグラフは置換して出力できる（グラフの同名の別顧客は置換先を選ぶ）。Excel で修復なしで開ける。合格

計測（基準ケース全体：マスタ xlsx 5・売上/仕入 CSV 各5・製造原価 xlsx 5、備考を文章内の置換、開発機）：計画 2.5 秒（要確認：規則の候補 1,258 件。大半は電話番号で一括操作で判断できる）、書出し 4.6 秒、検証 8.7 秒。

設計からの具体化・変更点：
- 判断の単位：短い語・置換先が複数の語は「表の定義・列」ごと、規則の候補は語句ごと。
- 同じ行の対象による置換先の決定を追加（備考の「〇〇様」は多くの場合その行の取引先を指すため。要確認を減らす）。
- 「担当:〇〇」の形の担当者名を規則の候補に追加（合成データの備考に担当者の姓だけが現れるため）。
- 追加語句（term 表）は使わず、対象の名称・別名・値対応として登録する。
- 新しく作る表の定義の表外の既定を「文章内の語句を置換」にした（06 章の設計どおり。既存の定義は変えない）。

後続に回したこと：
- 見出し（列名）の文章内の置換（見出しは表の定義の照合に使うため、置換する場合の扱いを決めてから）。
- 条件付き書式・入力規則・名前定義・図形・コメントの中の語句の置換（06 章 4.3）。
- 規則の候補の件数が多い場合の絞込み表示（種類別の表示・並び替え）。利用者の操作確認の結果を見て判断する。
