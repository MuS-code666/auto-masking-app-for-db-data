# 09 段階的な実装計画と受入条件

決定的な変換機能（設定・対応表・採番・変換・検証・出力）を先に完成・検証し、LLM による候補提案は後から追加する。各段階の終わりに合成データで受入条件を確認する。

段階0で判明した事項・後続への申し送り：
- 合成データの数式（製造原価.xlsx）は openpyxl で作成しているため**キャッシュ値を持たない**。段階2でキャッシュ値付きのブックを作る仕組み（自前の書込またはキャッシュ値の後付け）を追加する。
- プロジェクトフォルダのアクセス権を本人のみにする処理（07 章 6.3）は、プロジェクト作成画面とあわせて段階3で実装する。
- 依存のハッシュ付き固定は段階6（配布）で行う。現在は `requirements-dev.txt` で版のみ固定。

受入シナリオの確認（`tests/scenarios/`、合成データの CSV）：S1〜S8、S11〜S14 合格。S9・S10 は段階2（xlsx）・段階4（自由記述）で確認する。

計測（基準ケースの CSV 15 ファイル、開発機）：取込 0.7 秒、計画 0.5 秒、書出し＋検証 1.5 秒、確定＋公開 0.1 秒。08 章の暫定目標を満たす。

設計からの具体化・変更点：
- スキーマ v2 を追加（列の組の識別、作業ごとの仮登録の記録、要確認項目の重複防止など）。v1 のプロジェクトは開くときにバックアップを取って移行する。
- 同時に進められる変換作業は1つ（取込・判断の混乱を防ぐ）。
- 残存検査の辞書は「対象の元名称・別名・元コード・値対応の元値」。「内容削除」の列の元値は辞書に入れない（削除は機密語の指定ではないため）。計画で生成した値のセルは検査から除く（生成値には元の語句が含まれない）。
- 出力ファイル名の既定は「{表の定義名}_{連番2桁}.csv」。
- 「元データの誤りとして扱う」等の判断は作業単位。翌月の作業で同じ不一致があれば再度確認を求める（判断の引継ぎは段階3で検討）。

段階1で未対応（後続段階で対応）：
- 自由記述の検出・置換（段階4）。現在は列規則に「文章内を検査」を指定すると計画作成で停止する。
- 複合キー（段階3）。現在のコード体系は1要素のみ。
- 設定再利用の差分表示（列の追加・名前変更の候補）（段階3）。現在は見出しが完全一致する表の定義だけを適用。
- 表外の領域（見出し行より上）の処理指定。現在は維持し、残存検査の対象にしている（段階3で「文章内を検査」「内容を消す」を選べるようにする）。

## 受入シナリオ（依頼書13章）と検証方法

| No | シナリオ | 合成データと確認方法 | 段階 |
|---|---|---|---|
| S1 | 売上・顧客・製品の3ファイルで置換後も結合・集計できる | 3ファイルを変換し、元と出力で結合件数・顧客別/製品別の金額合計（変換後の名前で対応付け）が一致 | 1 |
| S2 | 翌月ファイルの既存顧客は同じ変換先、新規顧客だけ新番号 | 2か月分を別作業で取込。既存顧客の変換後名称・コードが同じ、新規顧客は既存の最大番号より後の番号 | 1 |
| S3 | 同じ文字列の顧客名と製品名は別種類として管理 | 顧客「さくら」と製品「さくら」→ 顧客000x と 製品000x に別々に置換 | 1 |
| S4 | 同一名称の異なる顧客を別コードから区別 | 同名で別コードの顧客2件 → 別の変換後名称。「同じ名称に複数のコード」が情報表示される | 1 |
| S5 | 略称・正式名を確認した別名登録で同じ対象につなぐ | 「さくら商事株式会社」と「さくら商事」→ 似た名称の要確認 → 別名登録 → 同じ変換後名称 | 1 |
| S6 | 金額・数量・日付を維持し、行数と対応関係が変わらない | V1, V2, V6 の合格 | 1 |
| S7 | 元からの未登録コードは不備として残り、変換由来の不備と区別 | 売上明細に顧客マスタにないコードを含める → 「元データ由来」として表示され出力可能。変換由来は0件 | 1 |
| S8 | 先頭ゼロ・空欄・重複・負数・小数・改行・日本語を含むCSV | それぞれの値を含む CP932 / UTF-8(BOM有無) / CRLF・LF のCSVで、維持値の完全一致と形式の再現 | 1 |
| S9 | 備考・ファイル名・シート名・コメント・非表示領域等の残存リスクを検出・明示 | それぞれに元語句を埋め込んだ xlsx → 置換または停止・明示される | 2, 4 |
| S10 | 未対応 Excel 機能で黙って破損・欠落させない | ピボット、外部リンク、未知部品、コメント、グラフ入りの xlsx → 停止または明示的な除去選択 | 2 |
| S11 | プレビュー・出力・再実行・再起動後も確定済み対応が変わらない | プレビュー時の番号を記録 → 出力 → アプリ再起動 → 再実行で同じ対応 | 1 |
| S12 | 途中キャンセル・出力失敗でマスタと成果物が矛盾しない | 各状態で処理を強制終了（試験用の中断点）→ 復旧後、対応表と外部出力が矛盾しない。取消した番号は欠番 | 1 |
| S13 | 異なるプロジェクトのマスタが混ざらない | 2プロジェクトで同じ顧客名 → それぞれ独立した番号。片方の対応表がもう片方に現れない | 1 |
| S14 | オフラインで変換でき、LLM不調時は手動設定で継続 | ネットワーク遮断環境で一連処理。LLM ワーカーを停止・異常応答させても完了 | 1, 5 |
| S15（追加） | 数式を含む xlsx で、数式を残したまま置換後も計算結果が整合する | VLOOKUP・SUMIF（顧客名の文字列定数）・IF・他シート参照・LEFT を含む合成ブック → 数式は維持、文字列定数とキャッシュ値が置換され、数値の計算結果が元と一致。LEFT 等は警告に出る。`"*さくら*"` 等の部分一致は停止 | 2 |

基準ケース（[08_performance_plan.md](08_performance_plan.md) 0.1：月次3種×5か月＋マスタ5種）の合成データで S1〜S15 を一括実行する試験を用意し、各段階の回帰試験とする。

## 開発上の約束

- 実データをリポジトリ・Claude Code に入れない。試験データはすべて合成データ生成器から作る。
- 各段階の変更は CLAUDE.md の Git 運用ルールに従いコミット・プッシュする。
- 新しい Excel 部品・機能に対応する場合は、[06_file_support.md](06_file_support.md) の対応表を先に更新する。
